4 Real Security Bugs in Node.js MCP Servers — Fixed With Zero npm Dependencies

By Daniel Lopes Published Nov 23, 2026 7 min read Node.js 18+/22 · Claude Code · Cursor · Windsurf

Most community Model Context Protocol (MCP) servers on GitHub pull in 140+ transitive npm packages, boot in ~310ms, and still fail four basic production security tests: symlink escape to .env, cloud metadata SSRF to 169.254.169.254, writable SQLite handles, and timing-unsafe webhook signatures.

The uncomfortable truth: you do not need an SDK tree to speak JSON-RPC 2.0 over stdio. Modern Node.js 22 ships node:fs, node:dns/promises, node:sqlite, node:crypto, and node:child_process out of the box — letting you build hardened MCP servers with 0 external dependencies, an 18ms cold start, and code your security team can audit in three minutes.

Bug #1: path.resolve() Does Not Stop Symlink Escapes

Almost every tutorial MCP filesystem server validates workspace boundaries with path.resolve(root, userPath).startsWith(root). That check is broken in two ways:

  1. Prefix confusion: /srv/workspace-secrets starts with /srv/workspace if you forget the trailing path separator.
  2. Symlink traversal: If an attacker (or a compromised repo commit) places a symlink at ./docs/readme-link → /home/dev/.aws/credentials, path.resolve() happily returns /srv/workspace/docs/readme-link — passing the string check while leaking host secrets into the LLM context window.

The Zero-Dependency Fix: fs.realpathSync() + Denylist

import fs from "node:fs";
import path from "node:path";

const SENSITIVE_RE = /(^|[\\/])(\.env(\..+)?|id_rsa|id_ed25519|\.npmrc|credentials\.json)$/i;

export function assertSandboxedPath(workspaceRoot, requestedPath) {
  const realRoot = fs.realpathSync(workspaceRoot);
  const candidate = path.resolve(realRoot, requestedPath);
  const realTarget = fs.realpathSync(candidate);

  const inside = realTarget === realRoot || realTarget.startsWith(realRoot + path.sep);
  if (!inside) {
    throw new Error(`Denied: symlink or path escapes workspace root (${requestedPath})`);
  }
  if (SENSITIVE_RE.test(realTarget)) {
    throw new Error(`Denied: sensitive credential path blocked (${path.basename(realTarget)})`);
  }
  return realTarget;
}
Audit note: Calling fs.realpathSync() resolves every symbolic link on disk before verifying the boundary with realRoot + path.sep. We also layer a deterministic denylist so even an in-repo .env.production cannot be exfiltrated by prompt injection.

Bug #2: Regex URL Filters Fail Cloud-Metadata SSRF

HTTP fetch and webhook MCP tools routinely try to block SSRF by matching localhost or 127.0.0.1 against the URL string. That is trivially bypassed by decimal IPs (http://2130706433/), IPv6 loopback ([::1]), HTTP 302 redirects, or a public DNS record resolving to 169.254.169.254 (AWS/GCP/Azure instance metadata).

The Zero-Dependency Fix: Resolve DNS First, Block Private CIDRs, Disable Blind Redirects

import dns from "node:dns/promises";
import net from "node:net";

function isPrivateIp(ip) {
  if (net.isIPv4(ip)) {
    const [a, b] = ip.split(".").map(Number);
    return (
      a === 10 || a === 127 || a === 0 ||
      (a === 169 && b === 254) ||
      (a === 172 && b >= 16 && b <= 31) ||
      (a === 192 && b === 168) ||
      (a === 100 && b >= 64 && b <= 127)
    );
  }
  const low = ip.toLowerCase();
  return low === "::1" || low.startsWith("fc") || low.startsWith("fd") || low.startsWith("fe80:") || low.startsWith("::ffff:127.");
}

export async function assertSafeExternalUrl(rawUrl) {
  const url = new URL(rawUrl);
  if (url.protocol !== "https:" && url.protocol !== "http:") {
    throw new Error(`Blocked protocol: ${url.protocol}`);
  }
  const records = await dns.lookup(url.hostname, { all: true });
  for (const { address } of records) {
    if (isPrivateIp(address)) {
      throw new Error(`Blocked SSRF target: ${url.hostname} -> ${address}`);
    }
  }
  return url;
}

Always pair this check with fetch(url, { redirect: "manual" }) and re-validate every Location header before following a redirect hop.

Bug #3: "Read-Only" SQLite MCPs That Only Check sql.startsWith("SELECT")

Checking whether an LLM-generated query begins with SELECT fails immediately against multi-statement payloads (SELECT 1; DROP TABLE invoices;), ATTACH DATABASE, or writable CTE mutations.

The Zero-Dependency Fix: OS-Level Read-Only Handle + PRAGMA query_only = ON

import { DatabaseSync } from "node:sqlite";

export function openReadOnlyDb(dbPath) {
  const db = new DatabaseSync(dbPath, { readOnly: true });
  db.exec("PRAGMA query_only = ON;");
  return db;
}

Even if an adversarial prompt tricks your SQL sanitizer, SQLite itself rejects every INSERT, UPDATE, DELETE, DROP, and PRAGMA write at the engine boundary — zero native C++ addons or better-sqlite3 rebuilds required on Node.js 22+.

Bug #4: String Equality (===) on Webhook HMAC Signatures

When MCP servers receive or dispatch signed webhooks (Stripe, GitHub, n8n), comparing hex digests with expected === received leaks timing side-channels and throws length mismatches. Use crypto.timingSafeEqual() after normalizing both buffers: 

import crypto from "node:crypto";

export function verifyHmacSha256(secret, payload, signatureHex) {
  const expected = crypto.createHmac("sha256", secret).update(payload).digest();
  const actual = Buffer.from(String(signatureHex || ""), "hex");
  return actual.length === expected.length && crypto.timingSafeEqual(expected, actual);
}
