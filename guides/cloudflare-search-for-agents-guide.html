3. The 4-Tier Cascade Discovery Pattern for AI Agents

Most websites in 2026 do not expose /.well-known/search yet. If your MCP server or agent tool hardcodes Tier 1 only, it fails on 95% of the web. Our open-source agent-search-mcp (MIT) and Edge API v1.1 run a deterministic 4-Tier Cascade with DNS-verified SSRF protection:

  1. Tier 1 — Native /.well-known/search: Probes OPTIONS, <meta name="agent:endpoint">, and sends RFC 10008 HTTP QUERY (falling back to GET ?q= / POST JSON).
  2. Tier 2 — Negotiated Markdown: Requests Accept: text/markdown, text/html;q=0.8 and parses x-markdown-tokens + YAML frontmatter.
  3. Tier 3 — Structured /llms.txt & /sitemap.xml: Fetches curated AI docs indexes and scores matching chunks with deterministic BM25.
  4. Tier 4 — Zero-Browser HTML Cleaning + BM25: Strips scripts, styles, navs, and footers in pure edge JS and ranks relevant paragraphs in milliseconds.

5. Blocking $0.75/1k Semantic Search Overage Spikes With WAF + Edge Cache

If you run native Cloudflare AI Search on paid zones, never leave /.well-known/search uncached or unthrottled. Three rules cut paid semantic query volume by 60%–85% immediately:

  • Edge Cache 5-minute TTL on normalized query strings (GET /.well-known/search?q=*) so repeated agent loops hit cache at $0.
  • Per-IP Rate Limiting (20 req / 10s) returning 429 with Retry-After to stop runaway agent loops and scrapers.
  • CI Budget Gate (budget-auditor.mjs) modeling monthly query spikes and exiting non-zero if projected overages exceed your cap.
